# Implementation Plan: picPac.by Collective Photo Album (Full-Stack MVP)

## 1. Архитектура системы (Full-Stack Overview)

Проект строится по гибридной схеме, сочетающей полноценный выделенный Backend-сервер для бизнес-логики, атомарных транзакций и интеграции с полиграфией **picPac.by**, а также **WebSockets / Realtime** для синхронизации холста в реальном времени.

```text
[ Flutter App (iOS / Android) ]
       │                  ▲
       │ REST API (HTTPS) │ WebSockets (Socket.io / WS)
       ▼                  │
[ Node.js + Express + TypeScript Backend ]
       │                  │
       ▼                  ▼
[ PostgreSQL (Sequelize) ]   [ S3 / Local Storage (Исходники и превью) ]
```

### Стек технологий:
* **Mobile Frontend:** Flutter 3.x (Dart 3), `flutter_riverpod`, `shadcn_ui`, `dio` (HTTP), `socket_io_client` (Realtime), `image_picker`, `flutter_image_compress`.
* **Backend Server:** Node.js, Express, TypeScript, `socket.io` (комнаты альбомов, присутствие, блокировки слотов), `multer` + `sharp` (обработка и нарезка превью фото).
* **Database:** PostgreSQL + Sequelize ORM (или Prisma/TypeORM).
* **Инфраструктура:** Docker + `docker-compose` (контейнеры: `postgres`, `backend`, `minio/storage`).

## 2. Пошаговый план разработки

### Фаза 1: Проектирование БД и Docker-окружение (Backend Base)
- [ ] **1.1. Контейнеризация (`docker-compose.yml`):**
  - Поднять `PostgreSQL 16` и настроить volume для данных.
  - Настроить папку/volume для хранения загруженных фотографий (`/uploads/originals` и `/uploads/thumbs`).
- [ ] **1.2. Схема базы данных (PostgreSQL + Sequelize):**
  - Таблица `Users` (беспарольные сессии по токену устройства): `id (UUID)`, `display_name`, `avatar_color`, `created_at`.
  - Таблица `Albums`: `id (UUID)`, `invite_code (6 символов)`, `title`, `host_user_id`, `total_pages (default: 20)`, `winning_cover_id`, `status ('draft' | 'voting' | 'locked' | 'ordered')`, `copies_count`.
  - Таблица `AlbumMembers`: `id`, `album_id`, `user_id`, `role ('host' | 'editor' | 'viewer')`, `joined_at`.
  - Таблица `Pages`: `id`, `album_id`, `page_number (1..20)`, `side ('left' | 'right')`, `layout_type ('grid_4' | 'split_2' | 'single')`.
  - Таблица `Slots`: `id`, `page_id`, `slot_index (0..3)`, `media_id (FK -> MediaPool, nullable)`, `caption (varchar 50)`, `author_name`, `locked_by_user_id`, `locked_by_name`, `locked_until (timestamp)`.
  - Таблица `MediaPool` (Общий мешок фото): `id`, `album_id`, `uploader_id`, `uploader_name`, `original_url`, `thumb_url`, `width`, `height`.
  - Таблица `SlotReactions`: `id`, `slot_id`, `user_id`, `emoji ('❤️' | '🔥' | '👍' | '😂')`.
  - Таблица `CoverVotes`: `id`, `album_id`, `media_id`, `user_id` (Unique index на `album_id + user_id` — 1 голос от участника).
- [ ] **1.3. Сидинг при создании альбома:**
  - Написать транзакцию: при создании нового альбома автоматически генерируются 20 записей в `Pages` и по 4 пустых слота в `Slots` на каждую страницу (всего 80 слотов).

### Фаза 2: REST API и обработка медиа (Backend Core)
- [ ] **2.1. Модуль авторизации и комнат (`/api/auth` & `/api/albums`):**
  - `POST /api/auth/guest` — принимает `display_name`, возвращает JWT-токен и профиль.
  - `POST /api/albums` — создание альбома организатором (возвращает `album_id` и 6-значный `invite_code`).
  - `POST /api/albums/join` — вход в альбом по `invite_code` или Deep Link.
  - `GET /api/albums/:id/full` — отдает полную структуру альбома: страницы, слоты, пул фото и текущие голоса.
- [ ] **2.2. Пайплайн загрузки фотографий (`/api/media`):**
  - `POST /api/albums/:id/media` — загрузка 1 или нескольких фото (`multipart/form-data`).
  - Серверная оптимизация через `sharp`:
    1. Сохранение оригинала в высоком качестве для будущей печати в **picPac.by**.
    2. Генерация легкого WebP-превью (`600x600px`, до 50 КБ) для мгновенной отрисовки в мобильной сетке.
  - Запись в `MediaPool` и отправка WebSocket-события `media:added` всем участникам комнаты.
- [ ] **2.3. Модуль заказа и B2B2C калькулятор (`/api/orders`):**
  - `POST /api/albums/:id/checkout` — доступно только для `role == 'host'`.
  - Валидация: проверка заполненности страниц, перевод альбома в статус `ordered`.
  - Расчет цены с учетом тиража (базовая цена + прогрессивная скидка за 10 / 20 / 30 экземпляров для классов и свадеб).
  - Формирование итогового JSON-манифеста заказа для типографии **picPac.by** (список страниц, привязка `original_url` к координатам слотов, подписи, выбранная обложка).

### Фаза 3: WebSocket-сервер для Realtime коллаборации (`socket.io`)
- [ ] **3.1. Управление комнатами и Presence:**
  - Событие `room:join` (`{ albumId, user }`) — добавляет сокет в комнату альбома, рассылает всем обновленный массив онлайн-участников `presence:update`.
  - Событие `disconnect` — автоматическое снятие всех активных блокировок слотов этого пользователя и обновление списка онлайн.
- [ ] **3.2. Атомарная блокировка слотов (Slot Locking):**
  - Событие `slot:lock` (`{ slotId }`):
    - Бэкенд проверяет в БД: если `locked_until < NOW()` или `locked_by_user_id == null`, записывает `locked_by_user_id` и `locked_until = NOW() + 60 sec`.
    - Рассылает всем в комнате `slot:updated`.
  - Фоновый таймер или проверка при запросе: автоматический сброс просроченных блокировок.
- [ ] **3.3. Операции со слотами, реакциями и обложкой:**
  - `slot:assign_media` (`{ slotId, mediaId, caption }`) — привязывает фото из пула к слоту, снимает блокировку, шлет `slot:updated`.
  - `slot:update_caption` (`{ slotId, caption }`) — обновляет подпись под снимком.
  - `slot:toggle_reaction` (`{ slotId, emoji }`) — добавляет/убирает реакцию, возвращает пересчитанные счетчики эмодзи.
  - `cover:vote` (`{ mediaId }`) — перезаписывает голос пользователя в `CoverVotes` и транслирует новый рейтинг обложек `cover:votes_updated`.

### Фаза 5: Мобильный клиент — Редактор разворотов (Thumb-Zone UI)
- [ ] **5.1. Стейт-менеджмент редактора (`Riverpod`):**

- [ ] **5.2. Верстка 5 эргономических зон (`SpreadEditorScreen`):**
  - **Зона 1 (Top Bar):** название альбома, стек аватаров онлайн с зелеными точками, кнопка шеринга кода комнаты.
  - **Зона 2 (Мини-карта страниц):** горизонтальный список страниц с индикацией заполненных слотов (`■ ■ □ □`) и рамкой `#FF4D4D` на текущей странице.
  - **Зона 3 (Фокус-страница + Линия безопасности):** белый лист `3:4` с тенью, пунктирной красной рамкой обреза и сеткой 2×2. Под листом — черная капсула переключения `[ ◀ Левая | Правая ▶ ]`.
  - **Зона 4 (Общий пул фото):** горизонтальная лента превью `54×54px` и кнопка `+ Загрузить с телефона` (с локальным сжатием перед отправкой).
  - **Зона 5 (Нижний док):** кнопки «👑 Обложка», «Сетка» и главная CTA «🛒 В заказ • X/20 стр.» (`#FF4D4D`).
- [ ] **5.3. Механика вставки «В 2 тапа»:**
  - Тап 1 по пустому слоту ➔ отправка `slot:lock`, слот красится в `#FFF0F0` с рамкой `#FF4D4D`.
  - Тап 2 по любому фото из нижней ленты «Общий пул» ➔ отправка `slot:assign_media`, фото мгновенно появляется в слоте.
- [ ] **5.4. Модалка слота (Подпись и Реакции):**
  - Тап по заполненному слоту открывает Bottom Sheet: крупное фото, поле ввода подписи (до 50 символов) и ряд быстрых реакций (`❤️`, `🔥`, `👍`, `😂`).
